**Skill = hur man gör en viss uppgift.**

En arbetsbeskrivning: "så skapar du en release", "så skriver du dokumentation". Bara namn och beskrivning ligger i kontexten – resten laddas när uppgiften dyker upp, eller när du kör den själv med /skill-namn.

En skill är en mapp: `.claude/skills/<namn>/SKILL.md`. Den kan innehålla fler filer och scripts – och det är poängen:
- **Extra filer läses bara när de behövs.**
- **Scripts körs utan att koden läses in** – bara resultatet kostar tokens. Då blir skillen mer som ett eget verktyg.

Exempel (Fikalistan):
```
.claude/skills/release/
├── SKILL.md              ← namn, beskrivning och stegen
├── checklista.md         ← läses bara när den behövs
└── scripts/
    └── bump-version.sh   ← körs, läses aldrig in
```

```
---
name: release
description: Skapar en release av Fikalistan – höjer versionsnummer,
  uppdaterar changelog och taggar i git. Använd när användaren vill
  släppa en ny version.
disable-model-invocation: true
---
1. Kör scripts/bump-version.sh
2. Uppdatera CHANGELOG.md utifrån commits sedan senaste taggen
3. Gå igenom checklista.md
4. Tagga: git tag vX.Y.Z
Gör aldrig: pusha taggen utan att fråga.
```
`disable-model-invocation: true` – bara du kan starta den, eftersom en release har sidoeffekter.


**Commands**
I Claude Code har commands och skills slagits ihop: både `.claude/commands/deploy.md` och en skill som heter deploy ger `/deploy`. Skillnaden är vem som får starta dem. Som standard kan både du och AI:n starta en skill. Med `disable-model-invocation: true` i frontmattern kan bara *du* göra det – bra för saker med sidoeffekter som `/deploy` och `/commit`.
