Huvudagenten promptar en annan agent.
Ett otydligt uppdrag ger ett dåligt resultat – och du ser bara sammanfattningen.

Kommer ni ihåg att en agent bara är en loop? Huvudagenten kan starta en ny loop och ge den ett uppdrag. Det finns två sorter: subagent och fork – mer om skillnaden på nästa slide. Du pratar normalt bara med huvudagenten: den skriver uppdraget, agenten gör jobbet, och bara slutsatsen kommer tillbaka. Allt agenten läser och söker igenom stannar i dess egen kontext. (I Claude Code kan du öppna en agents transcript och skriva till den, men det är undantaget.) Här kan information försvinna åt båda håll. På vägen ut: agenten kan inte fråga vad som menades, så ett otydligt uppdrag ger ett dåligt resultat – samma regler som när du promptar. På vägen tillbaka: du ser bara sammanfattningen, inte allt den hittade. Fördelarna: research, loggar och stora sökningar skräpar inte ner huvudsessionen, och flera kan jobba samtidigt – men ge tydliga instruktioner och avgränsningar så att de inte skriver i samma filer. Nackdelen: det kostar, varje agent är en egen loop. Huvudagenten matchar uppgiften mot agentens description – samma princip som för skills – eller så ber du om den, t.ex. ”låt code-reviewer granska det här”. Se anteckningarna i 2.6.3.1 Subagenter.
