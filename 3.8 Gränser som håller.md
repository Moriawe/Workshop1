
**Lagar som AI:n kan skriva om är inte lagar**
Skydd kan sitta på tre ställen. Ju längre ut i ringarna ett skydd ligger, desto säkrare är det. AI:n kan ändra en fil på din dator men inte branch protection på GitHub, inte rättigheterna i en token och inte kundens managed settings.

**1. I harness (Claude Code)**

- **Behörigheter** (allow/ask/deny): det vi redan har tagit upp.
- **Hooks** kan stoppa saker _före_ ett verktyg körs. De kan också köra kod _efter_, till exempel formatering och linter, eller hindra agenten från att avsluta innan testerna går igenom.
- **Sandbox:** körs kommandon i en sandbox begränsar operativsystemet vilka filer och vilket nätverk de kommer åt, oavsett vad modellen försöker.
- **Verktygslistan per subagent** (`tools`): en granskningsagent som saknar Edit kan inte ändra filer.
- **Plan-läget** ändrar ingenting.

**2. I miljön där den kör**

- **En container eller virtuell maskin:** den kan bara förstöra det som finns där inne. Det kopplar till din anteckning om Docker.
- **Tokens med minsta möjliga behörighet:** en GitHub-token som bara får läsa, eller en databasanvändare utan rätt att skriva. Det token inte tillåter går inte att göra. Det här är _starkt_ kopplat till din säkerhetspoäng från jobbet.
- **Filrättigheter och nätverksregler** på operativsystemnivå.
- **Budgettak på API-nycklar**, som kopplar till din del 5.

**3. I utvecklingsflödet**

- **Kompilatorn och typsystemet:** Kotlin och Swift släpper inte igenom typfel, hur säker AI:n än låter.
- **CI:** tester, linter, statisk analys och säkerhetsskanning. Ett rött bygge är rött.
- **Branch protection:** krav på PR, krav på granskning och krav på grön CI innan merge. AI:n kan inte trycka direkt till main.
  
  Det finns två fällor som är bra att visa:

- **Git pre-commit-hooks** körs lokalt. AI:n kan köra `git commit --no-verify` och hoppa förbi dem. Lösningen är att blockera `--no-verify` med en deny-regel eller hook, och att köra samma kontroller i CI.
- **Tester:** om AI:n får redigera testerna kan den “fixa” ett rött test genom att ändra testet i stället för koden. Skydda testfilerna eller granska ändringar i dem extra noga.

Ju längre ut i ringarna ett skydd ligger, desto säkrare är det. AI:n kan ändra en fil på din dator men inte branch protection på GitHub, inte rättigheterna i en token och inte kundens managed settings.
